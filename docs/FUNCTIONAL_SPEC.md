## 2. 产品定位

Content Publisher 的长期定位是纯个人内容生产与多平台发布工具，用于把可信技术资料转换为可追溯、可恢复、可多渠道分发的内容。产品不规划待审核、多级审批、多人协作、指派、评论或团队治理能力。

- 从 Git 项目、结构化主题或公开网站整理技术事实。
- 使用受控 AI 生成中文和英文技术内容。
- 统一管理标题、摘要、正文、标签、关键词和来源。
- 通过版本、发布前检查、任务日志和发布历史降低错误发布风险。
- 把一份主稿转换为不同平台需要的 Markdown、普通文本或短帖。
- 使用官方 API 自动发布，或通过合规人工工作区完成无稳定 API 平台的发布。
- 通过持久化任务、发布记录、监控和回收站处理长耗时任务与运营恢复。

当前 Portal 主流程已经使用个人内容确认和 `READY` 发布状态。多租户、Viewer/Editor/Admin、REST 审核 API、`APPROVED/REJECTED` 状态和部分旧错误码仍作为历史兼容边界保留；它们是当前代码事实，不是长期产品目标。后续收敛不能以删除文章版本、发布历史、任务日志、失败/重试或连接验证记录来替代流程简化。

## 3. 范围

### 3.1 当前范围内

- Git 项目导入、仓库分析和项目文章生成。
- 主题教程/指南类文章生成。
- 公开网站推荐文章生成。
- 租户级 AI 服务设置。
- 中英文内容、SEO 辅助、编辑、版本、个人内容确认和重新编辑。
- 用户级服务端草稿、自动保存和可复用生成预设。
- API 渠道账号生命周期和真实官方 API 发布。
- 17 个人工发布渠道及个人平台预配置。
- 时区化定时发布、发布日历、批量发布、取消和通用失败任务重放。
- 人工发布五项操作进度。
- 动作台、站内通知、通知确认和通知 Webhook。
- 渠道连接自动巡检、失败/恢复通知和低基数 Prometheus 指标。
- 发布统一记录、文章/渠道覆盖视图。
- 项目、内容、任务、发布、账号和渠道表现监控。
- 文章和任务软删除、关联记录隐藏与恢复。
- LOCAL 或 JWT 身份、RBAC、租户隔离和业务审计。

### 3.2 当前范围外

- 自动模拟登录、保存第三方密码、Cookie、验证码或绕过开放接口。
- 多用户协作、内容指派、评论、待审核队列、多级审批和团队治理。
- 新增独立审核历史模型；旧 REST 审核事实只作为兼容记录保存在审计日志。
- 主加密密钥在线迁移。
- UTM 策略、效果回收和 OAuth 到期提醒。
- 不确定外部发布结果的自动盲目重试。
- 自动修改或删除第三方平台上的已发布内容。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 租户 | 数据与权限隔离的组织边界 |
| 主稿 | 文章表中的可信中文/英文内容 |
| 派生内容 | 根据渠道格式从主稿转换出的发布内容 |
| 项目快照 | Git 仓库某次 Commit 的有限事实集合 |
| 持久化任务 | 保存到数据库、可查询和恢复的异步工作 |
| API 发布 | 平台调用官方 API 产生的发布 |
| 人工发布 | 用户复制派生内容，在官方页面发布并回填结果 |
| 人工平台配置 | 个人使用者为纯人工渠道保存启停、账号别名、默认标签/栏目、备注和排序，并通过独立持久浏览器 Profile 复用第三方登录会话 |

| 活动任务 | `PENDING`、`RUNNING` 或 `RETRY_WAIT` |

### 4.1 个人模式兼容边界

- 业务上按单人工作区使用，不新增协作关系或审批层级。
- 当前角色和租户结构继续用于认证、授权和数据隔离兼容，不能据此宣称已经完成单用户数据模型迁移。
- Portal 主流程为 `DRAFT → READY → PUBLISHED`，本人完成编辑确认后直接进入可发布状态。
- `APPROVED/REJECTED` 仅用于旧 REST 与历史数据兼容，不表示个人模式需要另一人审核。
- 多租户和角色结构仍用于认证、授权与数据隔离兼容；后续可以收敛，但必须保留不可变版本和发布前服务端校验。

## 6. 租户模型

- JWT 模式从可配置 Claim 读取租户；LOCAL 模式从本地用户读取租户。
- 客户端不能通过请求参数指定或切换租户。
- 项目、快照、文章、版本、用户草稿、生成预设、任务、通知、Webhook 端点与投递、人工发布进度、渠道账号、发布、人工发布、AI 设置和审计都按租户隔离。
- 同一 Git URL 可以由不同租户分别导入。
- 资源不存在和跨租户访问都表现为 404。
- 监控统计、发布列表和回收站只计算当前租户数据。

## 7. 内容来源

平台支持三类文章来源，最终都生成统一的 Article。

### 7.1 Git 项目

#### 输入

- Git HTTPS 地址，必填，最长 2048。
- 分支，可选，最长 255；为空时使用远程默认分支。
- `Idempotency-Key`，必填。

#### 地址规则

- 只允许 HTTPS。
- 禁止 UserInfo、查询参数和 Fragment。
- 主机必须在 `GIT_ALLOWED_HOSTS`。
- DNS 不得解析到回环、私网、链路本地或组播地址。

#### 仓库处理

- 使用 JGit 浅克隆，深度 1。
- 不递归克隆子模块。
- 限制超时、总大小、文件数、README 字符数和目录树范围。
- 临时目录在任务结束后清理。
- 提取项目名称、描述、默认分支、Commit、README、构建清单摘要、目录树、主要语言和 License。
- 项目状态为 `ANALYZING`、`READY` 或 `FAILED`。
- 只有 `READY` 项目可以生成文章。

#### 结果

生成文章来源类型为 `GIT`，保存项目 ID 和源 Commit，便于内容追溯。

### 7.2 结构化主题

#### 输入

| 字段 | 业务含义 |
|---|---|
| topic | 主题，最长 300 |
| description | 需要覆盖的背景和内容，最长 4000 |
| audience | 目标读者，最长 500 |
| articleType | 教程、知识指南、最佳实践、排障或概念说明 |
| knowledgeLevel | 入门、中级、高级或混合 |
| keywords | 最多 30 个期望关键词 |
| referenceNotes | 最长 10000 的参考说明 |

参考说明属于不可信输入，不能覆盖系统规则或要求执行外部操作。

#### 结果

来源类型为 `TOPIC`，文章不关联 Git 项目，保存主题、说明、受众、类型、知识级别和来源关键词。

### 7.3 公开网站

#### 输入

- HTTPS 网站 URL，最长 2048。
- 推荐角度，最长 2000。
- 目标读者，最长 500。
- 最多 30 个关键词。

#### 网站安全

- 只允许 HTTPS。
- 拒绝凭据、危险地址和不安全重定向。
- 不跟随任意重定向。
- 限制请求超时、响应字节数和提取文本字符数。
- 文本过短、响应过大或地址不安全时不创建文章。

#### 结果

来源类型为 `WEBSITE`，保存规范化 URL、页面标题、推荐角度和受众。网站内容只是事实材料，不能被当作系统指令。

## 8. AI 生成

### 8.1 租户级设置

Admin 可以配置：

- HTTPS OpenAI 兼容 Base URL。
- API Key。
- 模型。
- 5–300 秒超时。
- 0–1 温度。
- 启停状态。
- 原子设置版本。

API Key 使用 AES-256-GCM 加密后保存到数据库。页面和 API 不回显密文或明文。留空表示保留现有 Key，显式清除才删除。

租户配置优先于环境默认配置。每次调用前重新读取并校验地址。

### 8.2 通用生成策略

| 控制项 | 规则 |
|---|---|
| language | 必填，最长 20 |
| tone | 必填，最长 50 |
| minCharacters | 200–3000 |
| maxCharacters | 200–3000，且不小于最小长度 |
| maxKeywords | 1–30 |
| requiredKeywords | 必选词，数量不能超过关键词上限 |
| excludedKeywords | 最多 100 个禁用词 |
| requiredSections | 最多 20 个二级章节 |

同一关键词不能同时属于必选和禁用集合。

### 8.3 AI 输出

AI 返回中文和英文结构化字段：

- 标题、摘要、Markdown。
- 标签和 SEO 关键词。
- 英文标题、摘要、Markdown、标签和关键词。

### 8.4 确定性校验

服务端不直接信任模型输出：

- 中文标题、摘要和正文不能为空。
- 中文正文满足请求长度。
- 英文正文最多 3000 字符，轻微超限时收紧。
- 必选关键词必须出现，主关键词必须位于标题、摘要或正文前部。
- 禁用关键词不能出现。
- 必选章节必须形成 Markdown H2。
- 长文章必须有足够的 H2 结构。
- 中文标题最多 80 字符，英文标题最多 100 字符。
- 中文摘要最多 200 字符，英文摘要最多 320 字符。
- 标签和关键词去空、去重并限制数量。
- 不合格输出不会写入文章表。

### 8.5 SEO 辅助

- 第一项必选关键词优先作为主关键词。
- 识别教程、排障、指南、最佳实践或推荐等搜索意图。
- 优化标题、Meta Description、开头回答、H2/H3、长尾问题和 FAQ。
- 文章详情计算 100 分制 SEO 辅助分。
- 评分只用于编辑检查，不替代本人对来源和事实的核对。
- 不允许关键词堆砌、虚构统计、客户、评分、案例、兼容性或许可证。

## 9. 内容与版本

### 9.1 文章状态

```text
DRAFT ──本人确认──> READY ──至少一次成功发布──> PUBLISHED
  ▲                  │
  └────重新编辑──────┘

兼容：DRAFT/REJECTED ──REST approve──> APPROVED
      DRAFT/READY/APPROVED ──REST reject──> REJECTED
```

- 三类来源生成成功后都进入 `DRAFT`。
- `DRAFT` 和 `REJECTED` 可以编辑。
- `DRAFT` 或兼容 `REJECTED` 经本人确认后进入 `READY`。
- `READY` 和兼容 `APPROVED` 可以重新进入 `DRAFT`；`PUBLISHED` 暂不允许直接重新编辑。
- `READY`、`APPROVED` 和 `PUBLISHED` 不能直接编辑，避免发布基线被静默修改。
- `READY`、兼容 `APPROVED` 或 `PUBLISHED` 可以继续发布。
- Flyway V22 把迁移时已有的 `APPROVED` 数据回填为 `READY`；应用仍能读取后续由兼容 REST 产生的 `APPROVED`。

### 9.2 编辑与并发

- 每个主体可以为同一文章保存独立服务端草稿。
- 浏览器自动保存草稿，草稿记录保存 `baseVersion`；不创建正式版本。
- 正式保存仍必须匹配当前版本，草稿不能绕过并发冲突。
- 编辑请求携带 `expectedVersion`。
- 与当前版本不一致时返回 `ARTICLE_VERSION_CONFLICT`。
- 每次保存同时更新当前文章和新增不可变版本。
- 标题最长 500，摘要最长 2000，中英文正文各最长 20000。
- 标签最多 15，关键词最多 30。
- 可以从历史版本恢复内容；恢复同样创建新版本，不覆盖历史。

### 9.3 生成预设

- 预设按租户和来源类型 `PROJECT`、`TOPIC`、`WEBSITE` 隔离。
- 保存语言、语气、正文长度、关键词上限、必备章节和来源特定参数。
- 名称在同租户、同来源类型内唯一。
- 预设只填充生成表单，不绕过字段校验和来源事实边界。
- Admin 管理租户预设，Viewer/Editor/Admin 均可在创建内容时读取。

### 9.4 个人内容确认

- Editor/Admin 可以在 Portal 确认当前内容；`DRAFT/REJECTED → READY`。
- 对 `READY/APPROVED/PUBLISHED` 重复确认保持幂等，不重复写入确认审计。
- 确认产生 `ARTICLE_CONTENT_CONFIRMED` 审计事件。
- Editor/Admin 可以将 `READY/APPROVED` 重新进入 `DRAFT`，并产生 `ARTICLE_EDITING_REOPENED` 审计事件。
- 已发布文章不能直接重新编辑。
- 旧 REST `approve/reject` 仍仅允许 Admin 调用；驳回原因必填、最长 500，并继续产生兼容审计事件。Portal 不提供审核、批准或驳回入口。

## 10. 持久化任务

### 10.1 任务类型

- `IMPORT_PROJECT`
- `GENERATE_ARTICLE`
- `GENERATE_TOPIC_ARTICLE`
- `GENERATE_WEBSITE_ARTICLE`
- `PUBLISH_ARTICLE`

### 10.2 状态

```text
PENDING ──领取──> RUNNING ──成功──> SUCCEEDED
   │                 ├──临时故障──> RETRY_WAIT ──到期──> RUNNING
   │                 └──永久失败/次数耗尽──> FAILED
   └──领取前取消──> CANCELLED
```

任务保存进度百分比、短标签、详细说明、批次 ID、计划时间、租约、结果资源和有限错误。

### 10.3 幂等与配额

- 幂等键格式为 8–128 位字母、数字、点、下划线、冒号或连字符。
- 同租户同键同请求返回原任务或账号。
- 同键不同请求返回 409。
- 默认每租户最多 20 个活动任务。
- 批量发布在同一配额检查中创建全部子任务，配额不足时整体拒绝。
- 文章通过 `generation_job_id`、发布通过 `publication_job_id` 防止任务重放产生重复资源。

### 10.4 调度、取消与重放

- REST 发布请求使用 UTC `scheduledAt`；Portal 使用浏览器 IANA 时区输入并在服务端转换为 UTC。
- DST 不存在的本地时间被拒绝；歧义本地时间必须明确偏移，不能静默选择。
- 过去超过一分钟的计划时间被拒绝，最远一年。
- 到期前任务保持 `PENDING`，不会被工作器领取。
- 只有未领取的 `PENDING` 或 `RETRY_WAIT` 可以取消。
- Git、AI 和网站的明确临时故障可以指数退避重试。
- 发布外部 API 默认不自动重试结果不确定的调用。
- Editor/Admin 可以对 `FAILED` 任务创建新任务；原失败事实保留。
- 批量重放最多 20 个任务，先验证全部资源、权限、状态和幂等键，再原子创建。
- 发布任务若标记为外部结果不确定，则拒绝直接重放，必须先核对第三方平台。

### 10.5 租约恢复

- 默认租约 5 分钟。
- 工作器崩溃后，其他实例可以领取过期任务。
- 已达到最大尝试次数的过期任务进入 `FAILED`。
- 完成更新必须匹配任务 ID、`RUNNING` 和当前 `lock_owner`。

### 11.3 人工平台个人配置

- `/channels?view=manual` 合并 `ChannelCatalog` 官方目录与当前租户已保存的个人配置。
- 只允许为上述 17 个纯人工渠道保存配置；具有 API 发布能力的渠道不能进入该配置流程。
- 未保存配置的平台默认启用，并使用目录顺序作为默认排序。
- 可保存启停、个人账号别名、默认标签、默认栏目/分类、发布备注和 0–1000 排序值。
- 默认标签去空、移除开头 `#`、转小写并去重，最多 20 个，每项最长 60 字符；账号别名最长 120，栏目最长 200，备注最长 1000。
- 配置使用 `expectedVersion` 乐观锁；首次保存使用版本 0，已存在配置必须提交当前正版本。
- 停用的平台不出现在文章人工发布目标中，直接访问人工工作区或提交人工发布也会被服务端拒绝。
- 人工平台页面不再要求记录“已登录”时间；用户通过 `./scripts/dev browser` 启动独立持久浏览器 Profile，并在第一次使用时完成官方平台登录。
- 同一设备后续从该 Profile 打开系统和官方编辑器时，浏览器复用 Cookie、LocalStorage 和站点会话；平台主动注销、风控或会话过期时仍需重新登录。
- 官方入口只能来自 `ChannelCatalog`，用户不能保存任意平台 URL。
- PostgreSQL、Portal 表单和业务日志不保存第三方用户名密码、Cookie、Session、验证码或恢复码；Cookie 和 Session 仅保存在用户设备的专用浏览器 Profile。
- 历史 `/channels/manual/{channelType}/login-confirmation` Portal 路由和 `login_confirmed_at` 字段暂时保留用于兼容旧客户端与旧数据，但不再显示于当前主流程。

### 11.4 API 账号生命周期

- 只有 Admin 可以创建 API 账号。
- 创建请求必须有幂等键。
- 凭据字段必须精确匹配渠道定义，不接受多余字段。
- 凭据使用 AES-256-GCM 加密；HMAC-SHA256 指纹用于识别相同凭据。
- API 和页面不返回凭据或指纹。
- Admin 可以修改展示名称和安全地址、启停、轮换凭据和测试连接。
- 修改和轮换使用 `expectedVersion` 防止并发覆盖。
- 凭据轮换后清除旧连接验证结果。
- X/Reddit 发布前自动刷新 Access Token；新令牌按新账号版本加密保存。
- Medium 已有账号可以继续运行，但不能创建新账号。

### 11.5 地址安全

- DEV、GitHub、X、Reddit、Hashnode、Medium 使用固定地址。
- WordPress、Discourse、Mastodon、Ghost 使用租户地址。
- 动态地址必须 HTTPS、无 UserInfo/Query/Fragment、主机在允许列表且 DNS 为公网地址。
- 地址在创建、验证、预检和实际发布前重复校验。

## 12. 发布

### 12.1 内容适配

平台以主稿为唯一可信内容源：

- Markdown 长文渠道保留结构。
- 普通文本渠道去除 Markdown 标记。
- Twitter/X 和 Mastodon 生成 280/500 字符短帖。
- 小红书标题限制 20 个 Unicode 字符，并生成规范化话题标签。
- 派生内容不会覆盖主稿。
- API Publisher 和人工工作区使用同一个 `PlatformContentAdapter`。

### 12.2 发布预检

创建 API 发布任务前同时检查：

- 文章为 `READY`、兼容 `APPROVED` 或 `PUBLISHED`。
- 渠道账号属于当前租户且为 `ACTIVE`。
- 最近一次连接验证不能是失败。
- 渠道适配器存在且仍可运行。
- 地址安全。
- 凭据字段完整。
- 国外渠道具有完整英文标题、摘要和正文。
- `canonicalUrl` 合法。
- `scheduledAt` 合法。

页面禁用未通过预检的账号；直接调用 REST API 时服务端仍重新校验。

人工发布工作区同样要求文章为 `READY`、兼容 `APPROVED` 或 `PUBLISHED`，并要求目标人工平台处于启用状态。

### 12.3 canonical URL

- 只接受最长 2048、不含 UserInfo 的 HTTPS URL。
- DEV、Hashnode、Medium、Ghost 使用渠道原生 canonical/original 字段。
- WordPress、Discourse、GitHub Discussions、Reddit 附加原文链接。
- Twitter/X、Mastodon 在长度限制内附加链接。

### 12.4 API 发布

- 工作器创建 `PUBLISHING` 发布记录后再调用官方 API。
- 成功保存外部 ID、URL、发布时间，状态改为 `PUBLISHED`。
- 失败保存有限错误码和脱敏说明，状态改为 `FAILED`。
- 文章至少一次发布成功后状态改为 `PUBLISHED`。
- 外部结果不确定时不自动盲目重试，避免重复文章。

### 12.5 人工发布

1. Admin 可先在 `/channels?view=manual` 配置个人账号别名、默认标签、栏目、备注、排序和启停。
2. 用户通过目录中的官方入口在当前浏览器登录平台；需要时点击“确认已登录”保存人工时间标记。
3. Editor/Admin 从文章发布页进入已启用渠道的人工工作区。
4. 系统生成标题、正文和标签，并把平台默认标签与文章适配标签按顺序合并去重。
5. 用户可参考个人账号别名、默认栏目和发布备注继续调整派生内容。
6. 用户复制内容并打开官方创作入口。
7. 工作区按当前主体保存“复制标题、复制正文、打开编辑器、检查格式、已发布”五项进度。
8. 用户在第三方平台排版和发布。
9. 回填 HTTPS 公开 URL；服务端校验 URL 主机与渠道允许域名。
10. 保存最终派生内容快照、操作者和发布时间。

平台不保存第三方登录秘密，不检测第三方会话，也不执行浏览器自动化。“确认已登录”仅用于个人提醒。

### 12.6 统一发布记录

- API 与人工发布事实分别存储。
- 应用层合并为统一只读记录。
- 记录包含文章、渠道、方法、状态、账号或操作人、外链、有限错误和时间。
- 列表不返回渠道凭据或人工正文快照。
- 发布矩阵按文章与渠道展示最新状态；历史仍保留在统一时间线。
- 执行批次按 `batchId` 聚合同次多渠道任务。

## 14. 监控

监控快照按当前租户统计：

- 项目总数、窗口活动数和状态分布。
- 文章总数、窗口活动数、状态和来源分布。
- 任务总数、窗口活动数、总状态和窗口状态分布。
- 发布总数、窗口活动数和状态分布。
- 渠道账号总数和启停状态。
- 已覆盖渠道数。
- 每个渠道的总发布、成功和失败数量。

监控用于运营和运行态势，不等同于基础设施指标告警。

Actuator Prometheus 另外提供无租户/任务 ID 标签的低基数 Gauge：任务待执行、重试等待、运行、失败、最老待执行秒数，发布成功/失败和渠道验证失败数量。

## 15. 自动化与通知

- 自动化设置页同时展示项目、主题和网站三类来源的内置或自定义生成预设，并提供通知 Webhook 管理；预设表单按字段分组，服务端校验名称、来源、语言、语气、字符范围、关键词上限和来源特定字段，失败时保留输入并显示字段错误。
- 动作台汇总待本人确认内容、失败任务、已确认待发布文章和开放通知。
- 通知使用租户内 `dedupKey` 去重，可被当前用户确认；巡检恢复会关闭对应失败通知。
- 渠道巡检只处理超过陈旧阈值的账号，并在状态首次失败或从失败恢复时通知。
- Admin 可配置、启用、停用租户 Webhook，并向单个已启用端点异步排队测试通知；测试通知不会为其他端点准备投递。
- 自动化设置页仅显示 Webhook 主机和掩码路径，不把完整路径、查询参数或 fragment 写入 DOM；最近投递展示状态、尝试次数、时间和有限错误摘要。
- 每个“通知 × 端点”只有一个投递记录。
- Webhook Payload 只包含有限通知字段，不含租户秘密、正文或凭据。
- 失败投递指数退避，达到配置上限后保持 `FAILED`，不会无限重试。
- Webhook URL 在保存和每次投递前执行 HTTPS、公网 DNS 和地址策略校验；生产仍需出站网络 ACL 防御 DNS rebinding。

## 16. 回收站

- Admin 可以软删除文章或终态任务。
- 活动任务不能删除。
- 文章仍有关联活动任务时不能删除。
- 删除文章同时软删除与文章关联的任务和发布事实。
- 删除生成任务时，如果存在由该任务生成的文章，则级联删除整条文章记录。
- 恢复文章同时恢复关联任务和发布事实。
- 回收站查询每类最多返回 100 条。
- 当前没有永久清理接口。

## 17. 身份与安全

### 17.1 LOCAL

- PostgreSQL 保存本地用户和角色。
- 密码保存 BCrypt 哈希，强度 12。
- 新密码 8–128 位，必须同时包含大写、小写、数字和特殊字符。
- 禁止重复使用当前密码。
- Session 采用固定攻击防护，默认最多一个并发会话。
- Web 写操作启用 CSRF。

### 17.2 JWT

- Bearer Token 至少提供主体、租户和角色。
- API 无状态。
- Claim 名可以配置。

### 17.3 DISABLED

- 仅本地开发。
- 使用服务器配置的默认租户和主体。
- 生产禁止使用。

## 20. 错误与用户反馈

应用错误和参数校验错误包含 UTC 时间、HTTP 状态、稳定错误码、可理解说明、请求路径、Trace ID 和字段错误。认证失败、权限不足和强制改密由安全过滤器返回最小安全错误体，只包含状态、错误码和说明。后台页面的 400、401、403、404、405 和 500 使用中文兜底页并保留原 HTTP 状态；`/api/**` 错误继续返回 JSON，不展示 Whitelabel 页面、堆栈或内部异常详情。

用户界面必须处理：

- 空列表和首次使用。
- AI、渠道或工作器未启用。
- 项目未就绪。
- 加载和自动刷新。
- 权限不足和强制改密。
- 表单校验、版本冲突和重复提交。
- 外部服务超时、地址拒绝和响应不合格。
- 任务取消、失败和人工重试。
- 长标题、长正文、长错误信息和移动端布局。
- 跟随系统、浅色和深色三种外观下的文字、控件、表格、状态和焦点可见性。

错误提示应说明原因和下一步，不显示堆栈、密钥、内部路径或 SQL。

## 22. 验收标准

### 22.1 内容来源

- 安全 Git 地址可以创建导入任务，不安全地址在入队前被拒绝。
- 项目快照保存 Commit、分支、README、Manifest、目录树、语言和 License。
- 主题请求保存主题、受众、类型、知识级别和来源关键词。
- 网站请求拒绝危险地址、重定向、过大响应和过短内容。
- 三类来源都生成统一文章，并能在内容库按来源识别。

### 22.2 AI 与内容

- 租户 AI API Key 只以认证密文保存且不回显。
- AI 输出违反长度、必选词、禁用词、章节或标题摘要规则时不写入文章。
- 编辑必须匹配 `expectedVersion` 并创建新版本。
- 历史版本恢复不覆盖原版本。
- Editor/Admin 可以确认内容；`READY` 可以发布，未确认的 `DRAFT/REJECTED` 不能发布。
- 兼容 REST 审核/驳回仍只有 Admin 可以调用。
- 国外渠道缺少英文稿时预检失败。
- 草稿按主体隔离，自动保存不创建正式版本；预设不能绕过生成校验。

### 22.3 任务

- V1–V22 可从空库连续执行，V22 将已有 `APPROVED` 回填为 `READY`。
- 异步写接口返回任务和正确状态码。
- 同幂等键同请求返回原结果；不同请求返回冲突。
- 不同租户可以使用相同幂等键。
- 两个工作器不能同时成功领取同一任务。
- 临时故障退避，次数耗尽后失败。
- 过期租约可以恢复。
- 计划时间到达前任务不能被领取。
- 未领取任务可取消，RUNNING 和终态不可取消。
- 单个和最多 20 个失败任务可重放，新任务与原失败事实同时保留。
- 批量重放任一任务不合格时不创建任何新任务。
- 外部发布结果不确定时重放被拒绝。

### 22.4 渠道与发布

- API 查询不返回渠道凭据或指纹。
- 凭据轮换拒绝过期账号版本。
- 自托管地址通过 HTTPS、允许列表和公网 DNS 校验。
- Medium 不能新建账号，已有账号仍可运行。
- X/Reddit 刷新后的凭据以新版本加密保存。
- API 发布成功保存外部 ID、URL、时间和审计。
- 人工发布外链必须匹配渠道域名。
- 统一记录不暴露人工正文快照。
- 批量发布最多 20 个去重账号，并生成可聚合批次。
- Portal 时区计划正确转换 UTC，DST 间隙与歧义得到明确处理。
- 人工发布五项进度按主体隔离且可恢复。
- 17 个人工平台未配置时默认启用，可保存别名、默认标签/栏目、备注、排序和启停状态。
- 停用平台不能出现在文章目标列表，也不能通过直接 URL 或表单绕过服务端门禁。
- 默认标签与文章适配标签合并去重；配置并发更新拒绝过期版本。
- 页面和表单不包含密码、Cookie、Session、验证码或恢复码字段；专用浏览器 Profile 跨浏览器重启复用平台会话，历史登录确认能力不再出现在 Portal。
- API 渠道不能伪装为纯人工平台进入个人配置流程。

### 22.5 权限、租户与恢复

- Viewer 不能调用写接口。
- Editor 可以确认和重新编辑未发布内容，但不能调用兼容 REST 审核、管理渠道、AI 设置或回收站。
- 不同租户不能读取彼此资源或统计。
- 强制改密用户不能访问业务功能。
- 活动任务和有关联活动任务的文章不能删除。
- 恢复文章时关联任务和发布事实同步恢复。
- 外观可以在跟随系统、浅色和深色之间循环切换，刷新页面后保留当前浏览器选择；跟随系统时响应系统配色变化。
- 深色主题下正文和关键控件文字对比度不低于 WCAG AA 正文要求，焦点和图形边界清晰可辨；业务状态仍有文字或形状信息。

### 22.6 自动化与运维

- 渠道巡检在失败/恢复转换时产生去重通知。
- Webhook 每个通知和端点只投递一次成功事实，失败按上限退避。
- `./scripts/dev verify` 可以作为完整验证入口。
- `./scripts/openapi check` 能发现未同步的接口合同变化。
- 应用启动时 Flyway 和 Hibernate Schema 校验通过。
- health、liveness、readiness 可用于探针。
- 生产部署有数据库、环境文件、主密钥和制品备份。
- 回滚前检查 Schema 兼容和正在执行的外部发布。
