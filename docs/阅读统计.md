# 发布阅读统计

维护者：修改发布统计功能的开发者。本文补充[业务说明](FUNCTIONAL_SPEC.md)、[技术设计](TECHNICAL_DEVELOPMENT.md)、[接口参考](API_REFERENCE.md)和[运维说明](OPERATIONS.md)，描述当前实现，不代表生产已发布。

## 使用方式与口径

- 从“发布中心 → 发布记录”或文章发布页的成功记录进入“更新统计”。每条实际发布记录独立保存，同平台不同账号、重复发布之间不合并。
- 所有成功发布记录都可手动录入“阅读 / 浏览次数”和“去重阅读人数”。至少填写一项；未知项留空，真实零值填 `0`。只接受 `0` 到 `9223372036854775807` 的整数；同时提供时去重人数不能超过次数。
- 页面展示数值、来源（官方接口或手动录入）、记录时间、同步尝试时间和失败信息。记录时间是本系统保存快照的 UTC 时间，不保证等于平台统计截止时间。
- 未录入、未同步与真实零值分开。只提供次数时显示“去重人数未提供”；不推算人数，也不对各平台人数求和。
- DEV、Discourse 的成功 **API 发布记录**支持点击同步。人工发布记录没有绑定原 API 账号，仍采用手动录入。
- 同步成功替换当前统计，接口不提供的去重人数会清空；页面事先说明，并通过既有确认交互提示。同步失败保留原数值、来源和记录时间，不改成零。
- 无接口、无权限、账号已停用或移除时可手动录入。不抓取平台后台，不收集 Cookie，不使用文章链接作为请求地址。
- Viewer 只读；Editor、Admin 可录入和同步。统计只对当前租户可见。

## 已接入接口

| 渠道 | 请求 | 取值与凭据 |
|---|---|---|
| DEV Community | `GET https://dev.to/api/analytics/totals?article_id={externalId}` | `page_views.total`，`api-key`，使用原发布记录的文章编号和原账号 |
| Discourse | `GET {validatedBaseUrl}/t/{externalId}.json` | 根节点 `views`，同时核对 `id`；`Api-Key`、`Api-Username`，使用原发布账号 |

接口依据：[Forem 官方 API 文档](https://developers.forem.com/api/v1)、[Forem AnalyticsService 返回结构](https://github.com/forem/forem/blob/main/app/services/analytics_service.rb)、[Discourse 官方 OpenAPI](https://docs.discourse.org/openapi.json)。这两类指标都是平台定义的浏览次数，不是跨平台去重阅读人数。

公众号及其他渠道暂未接入自动统计。已有渠道发布能力不代表平台开放读取文章数据的权限；本实现不承诺每个账号的分析接口均可用。

## 接口、安全与失败处理

Portal 路径前缀为 `/publishing/articles/{articleId}/readership/{method}/{publicationId}`，`method` 为 `API` 或 `MANUAL`：

| 方法 | 用途 | 权限与结果 |
|---|---|---|
| GET 前缀 | 查看、录入页 | Viewer/Editor/Admin；200 HTML，资源无效按既有 Portal 规则 400 |
| POST 前缀 | 手动录入 | Editor/Admin + CSRF；表单 `version`、可空 `views`、可空 `uniqueReaders`；成功 302 到本页，输入错误或版本冲突回显原输入 |
| POST 前缀 + `/sync` | 读取官方浏览次数 | Editor/Admin + CSRF；表单 `version`；302 到本页并显示结果 |

服务端核对文章租户、发布记录归属及 `PUBLISHED` 状态。同步还要求原 API 账号未移除且处于 `ACTIVE`，以及 `PUBLISHER_CHANNELS_ENABLED=true`；沿用既有渠道凭据、加密和配置，不增加环境变量。

外部编号只允许最多 19 位正十进制数字。请求端点通过既有 `ChannelEndpointPolicy` 校验：DEV 固定官方域名；Discourse 必须符合 HTTPS、允许列表及公网解析规则。沿用不跟随重定向的渠道客户端，不访问 `externalUrl`。不持久化或展示平台原始响应、异常细节、凭据。

单次完整响应最多等待既有 `PUBLISHER_CHANNEL_TIMEOUT` 与 15 秒的较小值；响应体上限 2,000,000 字节。单进程最多两个统计同步，同一发布记录两次同步开始至少间隔 30 秒。没有后台定时采集、自动重试或页面 GET 隐式外部请求。

同步先以版本条件写入尝试时间，再调用接口，最后再次按版本保存。期间发生手动修改时，迟到的结果和失败提示不能覆盖新值。网络中断或进程退出可能只留下尝试时间；页面显示“同步进行中或未完成”，30 秒后可重试。

常见业务错误包括 `READERSHIP_INVALID`、`READERSHIP_NOT_FOUND`、`READERSHIP_CONFLICT`、`READERSHIP_UNSUPPORTED`、`READERSHIP_ACCOUNT_UNAVAILABLE`、`READERSHIP_COOLDOWN`、`READERSHIP_BUSY`、`READERSHIP_PERMISSION`、`READERSHIP_TIMEOUT`、`READERSHIP_RESPONSE_INVALID`。这些是 Portal 表单提示，不新增 `/api/v1` 或 OpenAPI 合同。

## 存储、迁移与回滚

应用层由 `ReadershipApplicationService` 统一核对发布事实、校验和版本更新；`ReadershipRepository` / `JdbcReadershipRepository` 负责带租户的查询和条件写入。`PublicationReadershipReader` / `OfficialPublicationReadershipReader` 隔离外部 HTTP；`PortalReadershipController` 负责 HTML 表单，既有发布页批量读取快照而不逐行访问平台。以上组件通过现有基础设施配置装配；领域层不依赖 Web 或 JDBC。

Flyway **V26** 新增 `publication_readership`。主键为 `(tenant_id, publication_method, publication_id)`，`article_id` 为文章外键并有租户文章索引。多态发布记录引用由应用层验证。保存最新次数、人数、来源、记录时间/操作者、最近同步尝试时间/安全错误和乐观锁版本；不存访问者身份、浏览事件、历史趋势或平台响应。

部署前按[运维说明](OPERATIONS.md)备份数据库及旧制品；不修改已发布的 V1–V25。新版本启动自动前向迁移。迁移后应验证：

```sql
select version, success from flyway_schema_history where version='26';
select tenant_id, publication_method, publication_id, views, unique_readers,
       source, recorded_at, last_sync_at, version
from publication_readership limit 10;
```

第二条查询应在受控运维终端检查，不把生产统计放入共享日志。验收至少包括隔离数据录入、刷新保留、只读权限、错误同步保留旧值以及 readiness。

V26 只增加独立表，不改变旧表、枚举或已发布迁移。旧应用不读取该表；回滚应保留统计表和 Flyway 历史，恢复兼容旧制品后检查 readiness。必须先验证目标旧版 Flyway 对较新迁移的处理；不能修改校验和、删除 V26 历史或手动删表来绕过检查。若目标版本无法接受新迁移，按既有方案恢复迁移前备份，并先保存需要保留的新统计数据。旧版不展示统计属于预期限制。

## 验证与当前限制

- `ReadershipApplicationServiceTest`：未知/零值、手动计数规则、成功记录门禁、同步覆盖、失败保留、冷却和迟到结果竞争。
- `OfficialPublicationReadershipReaderTest`：本地模拟 HTTP 验证真实路径和 JSON 口径、认证 Header、数字边界、无重定向、响应大小、完整响应超时；不调用真实平台。
- `ReadershipIntegrationTest`：H2 PostgreSQL mode 下执行 V26，验证列表/表单、保存回显、乐观锁、租户、Viewer/Editor/Admin 与 CSRF。
- 真实 DEV / Discourse 账号权限和平台实际指标尚需配置账号后验证；本地模拟通过不等于真实平台联调完成。
- 当前只保存最新快照，没有定时同步、历史曲线、增长率、跨平台人数去重或公众号自动数据采集。

统计页属于私有后台，服务端渲染并保持 `noindex,nofollow`，不加入 Sitemap；无新增前端框架、追踪脚本或依赖。
