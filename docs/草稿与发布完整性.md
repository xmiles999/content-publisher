# 草稿与发布完整性

本文描述 2026-10-30 工作区实现，适用于个人写稿、人工发布准备、API 发布计划与配图导出。维护者修改这些流程时同步本文、业务和接口说明。生产是否采用此实现，以发布检查记录为准。

## 已实现能力

### 新建与人工渠道草稿

- 直接编写新稿时，标题、正文、摘要、标签、关键词、语言及英文内容允许在不完整状态下自动保存，不会提前创建正式文章。
- 每个租户与账号有一份正在新建的草稿；重新进入“写新稿”恢复服务端内容。其他写作来源的生成表单不属于本功能。
- 人工标题、正文、发布链接按“租户、账号、文章、平台、语言、主稿版本”保存，重新打开同一工作区可继续。恢复准备稿时不自动再次调用付费字数优化。
- 步骤进度与平台准备稿分别保存；完成外部发布并提交成功后，才生成正式人工发布记录。
- 输入后约 900ms 自动保存，请求串行，超时 15 秒；未收到有效 JSON、修订号和保存时间不显示成功。
- 服务端采用修订号条件写入；旧标签页或另一设备的旧修订返回 HTTP 409，保留当前输入并暂停覆盖。正式提交也核对修订号。
- 正式提交等待准备稿保存完成。网络失败、冲突及本机存储不可用都会提示；应急数据使用按账号与工作区隔离的当前标签页 `sessionStorage`。
- 消费工作区草稿后清空内容，保留递增修订号，防止旧标签页覆盖下一份新稿。
- 主稿自动保存增加独立 `revision`；Portal 携带该值条件保存，完成正式保存时不删除其他页面后来写入的草稿。

### 发布计划绑定版本

新提交的单渠道与批次任务在 `JobPayload.PublishArticle.articleVersion` 中保存服务端接收时的主稿版本。执行时校验确认状态与版本；平台适配、AI 压缩、凭据刷新结束后，在调用外部平台前再次校验。

主稿变化后计划停止发送，需核对并重新创建计划。此实现采用“版本变化则停止”，不承诺继续发送旧版不可变快照。手动重试保留原版本；失效或未绑定版本的历史计划不能直接重试。旧任务不猜测、不回填历史版本；已有成功结果仍可复用。

任务详情显示绑定版本和重建入口。发布完成仅在文章版本仍匹配、状态仍可发布时更新 `PUBLISHED`，不会回写旧正文或把较新的修订错误标成已发布。

### 配图检查和下载

- 编辑页“导出已保存稿与配图”返回认证后的 ZIP，包含 `article.md`、非空时的 `article.en.md`、本篇图片及 `发布说明.txt`。
- 导出使用正式保存的主稿，编辑区未保存内容不进入包；系统生成的后台相对图片地址替换成包内 `assets/` 路径。
- 文件只从本租户、本篇文章存储读取，不抓取外部图片、不导出凭据。附件合计上限 25MiB，超过上限需分张保存。
- API 预检和执行遇到后台配图路径会停止，说明先上传图片并替换地址，或使用人工流程。
- 人工发布页遇到后台配图提供提醒和下载入口；图片仍需在目标平台上传和核对。
- 下载设置 `Cache-Control: no-store`、附件 disposition 和 `X-Robots-Tag: noindex,nofollow`；原有认证与私有页面索引策略保留。

## 接口与存储

| 入口 | 规则 |
|---|---|
| `PUT /articles/workspace-drafts/{key}` | Portal JSON 辅助请求；Editor/Admin；LOCAL 模式要求 CSRF；不进入 OpenAPI |
| 新建 key | `new` |
| 人工 key | `manual:{articleId}:{channelType}:{original或en}:{主稿版本}` |
| 请求 | `{"revision":0,"fields":{"title":"未完成标题","markdown":""}}`；首次 0，后续使用返回修订号 |
| 响应 | `fields`、`revision`、`updatedAt`；409 不覆盖已有稿 |
| `GET /articles/{articleId}/export` | Viewer/Editor/Admin；本租户文章；ZIP 下载，不进入 OpenAPI |
| 主稿草稿 API | 原 `/api/v1/articles/{articleId}/draft` 增加可选请求 `revision` 和响应 `revision` |

`fields` 只允许对应表单字段并逐字段限制长度：正文 100000、标题 500、摘要 2000、新建标签文本 1000、关键词文本 3200、语言 20、平台链接 2048。允许空字段保存未完成输入；正式提交仍执行原业务校验。

Flyway V27 给 `article_drafts` 增加 `revision`（既有记录从 1 开始），新增 `workspace_drafts`，主键为 `(tenant_id, actor_subject, draft_key)`，内容为字段 JSON。归属来自认证上下文，不接受客户端指定。主稿旧 API 不传 `revision` 时保留兼容写入；需要跨页面冲突保护的客户端必须使用修订号。

## 当前限制

- 自动保存成功前立即关页仍可能丢失最后输入；应急数据不保证关闭标签页、浏览器或换设备后恢复。服务端成功保存的稿可跨设备读取。
- 新建稿当前每账号一个工作区，尚不支持多份命名新建稿。
- 主稿版本变化后不会自动合并旧平台稿；旧稿数据保留，修订前应先保存或复制需要的内容。
- 主稿兼容客户端不传修订号时仍可能最后写入覆盖；此兼容行为不等于多人协同编辑。
- 历史“平台已发布”仍表示历史成功，尚未完成按平台、语言及最新版本的覆盖状态模型。
- ZIP 是基础正文和图片导出，不包含全部版本、统计、发布历史、外部图片或完整元数据，不能代替数据库和附件备份。
- 未实现平台媒体 API 自动上传；自定义绝对地址、跨文章引用及目标平台排版需要用户检查。
- 本批未升级依赖、执行生产迁移或发布。
