# UI 与功能优化实施记录

## 目标与约束

将个人文稿的写作、确认、渠道发布和结果追踪逐批优化。沿用 Spring MVC、Thymeleaf 与原生 CSS/JS，不引入第二套前端框架；所有后续项都要验证后才能标记完成。

维护者：修改对应功能的开发者；项目所有者确认产品规则。业务合同见[业务说明](FUNCTIONAL_SPEC.md)，架构见[技术设计](TECHNICAL_DEVELOPMENT.md)，运行与测试见[开发文档](开发文档.md)。

## 平台限长 AI 优化与发布状态修正（2026-10-27）

### 当前实现

- 按用户选择优先使用当前租户已配置 AI 压缩超限渠道文案；一般 Unicode 码点、X 保守加权与 X/Mastodon 链接默认 23 字计数前后端一致，链接后的中文标点另计。标题限制集中维护，正文沿用目录默认参考值，不把目录默认值当作实时平台配额。
- 人工工作区首次进入且超限时自动请求一次，未超限不调用；结果可编辑、可撤销，生成期间编辑不覆盖，错误表单回显不再次自动调用。主稿、正式版本和自动草稿不变，派生正文仍只在提交发布事实时留档。
- 超限或正在生成时暂停复制和页面提交；修改平台正文后禁用主稿富文本复制，避免从旧主稿绕过压缩文案。被阻止的提交保留离开提醒。
- API 预检不调用 AI，实际任务超限时才压缩，输出重新校验后才调用平台；保留已附加的 canonical 链接。AI 关闭、失败、响应异常、仍超限或并发满额时不硬截断，不自动重试优化。单次优化最多 60 秒，每进程并发最多 2，复用原有租户配置、凭据保护和 SSRF 策略。
- 文章发布页按渠道成功记录显示“已发布 / 查看结果”，尚未成功的平台继续“准备发布”；重复操作收进“更多 → 再次发布”。人工和 API 历史成功均有效，后续失败保留原成功结果；历史成功不代表当前主稿修订已同步。
- 本批限长优化没有新增依赖、迁移或生产环境变量；Portal JSON 辅助请求不进入 OpenAPI，原 `/api/v1` 快照保持不变。本批不增加阅读统计采集。

## 渠道精简与覆盖修正（2026-10-27）

### 当前实现

- 保持 27 种渠道与 24 个人工入口，不增加平台、依赖、迁移或新的 REST 字段。
- `/channels` 默认“我的渠道”；未配置的平台不自动启用，已保存状态不变。配置后默认只显示启用平台，可切换“显示全部平台”添加其他平台；无 JavaScript 时仍展示完整目录。
- 可勾选后统一保存，或先选择常用中文平台、清空选择；后两者只改变待保存状态。保存携带全部版本号，在单事务内修改启停，保留别名、默认标签、栏目、备注、排序和登录确认字段。版本冲突或唯一约束冲突整体回滚。
- 去除渠道表中重复的登录方式、更新时间两列；手机端显示勾选、平台、个人设置与配置操作。未保存的勾选有离开提醒，单纯切换显示范围不触发提醒。
- 覆盖矩阵合并启用人工平台与 ACTIVE、目录允许已有账号运行的 API 渠道，按平台去重；保留最近成功链接及后续失败提示。未发布格可直接进入发布页，未发布筛选明确只作用于当前页。
- API 发布和适配使用主稿；人工发布默认主稿，可选择已有完整英文稿，不按地区强制语言。旧的未执行 API 任务也会按主稿适配，使用者应核对主稿语言。
- 人工文章平台新增“复制主稿富文本”，复用安全 Markdown 渲染器，向剪贴板写入 HTML 与纯文本。富文本取自所选主稿，不包含平台文本框的后续修改；图片仍需在平台检查或上传。
- 普通或富文本复制失败时提供提示，不虚报复制进度；普通复制失败不打开外站。旧 `/channels#account-*` 链接在浏览器中进入 API 页签，新的 API 表单返回显式 API 页签。

## 第一批：写作与查询可信度（2026-09-26）

### 已实现

- 编辑页默认折叠摘要、标签和关键词；辅助信息不再固定占据右侧 330px。
- 提供编辑、分栏、预览切换，记住非敏感显示偏好；小屏不堆叠两个正文区域，操作栏不固定遮挡输入。
