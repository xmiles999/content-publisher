# 平台文案规范

核对日期：2026-11-11。适用版本：`0.1.0-SNAPSHOT`。面向内容使用者与生成适配器维护者，由修改生成提示词的维护者同步更新；业务入口见[业务说明](FUNCTIONAL_SPEC.md)，实现见[技术设计](TECHNICAL_DEVELOPMENT.md)。

## 来源与有效性

本轮先接入小红书。生成器中的规则是写作提示约束，不是官方审核接口、敏感词数据库或实时规则订阅，也不保证过审或流量。

| 官方来源 | 本次核验与边界 |
|---|---|
| [小红书社区公约](https://www.xiaohongshu.com/crown/community/agreement)及其[公开正文数据](https://pages.xiaohongshu.com/data/community_agreement2) | 已读取正文，数据中的更新日期为 **2023-02-23**，不能据此宣称已覆盖截至核对日的全部最新规则 |
| [社区规范入口](https://www.xiaohongshu.com/crown/community/rules) | 页面可访问，但动态条文接口本次返回 HTTP 405，未完整核验正文 |
| [规则中心](https://www.xiaohongshu.com/picasso_pages/author-center/rule-center?fullscreen=true&source=agreement) | 来自公约正文的官方跳转地址；发布者需按账号、内容类目和发布形式核对最新专项规则，本次未完整核验 |
| [创作服务平台](https://creator.xiaohongshu.com/) | 入口可访问；账号权限、字数、商业报备和 AI 标识的最终要求需在实际发布入口确认 |

不以运营博文、所谓违禁词合集或模型记忆代替官方来源。规则发生变化时，先记录官方出处和适用范围，再修改提示词与回归断言；无法核实的要求只能标为内部策略或待核实。

## 已核实的公约方向

以下是上述公开正文的概括，按原文的适用场景理解，不扩大为所有内容都禁止商业表达或互动。

| 公约方向 | 生成约束 |
|---|---|
| 尊重原创、分享真实内容，转载需授权并注明出处 | 不抄袭，不虚构亲测、效果、评价、资质或背书，不编造引用 |
| 受到商家赞助或便利需声明利益相关 | 已知赞助、赠品、合作关系如实表达，不捏造合作或已经完成报备的事实 |
| 文题相符，避免夸张猎奇、误导性修饰及伪科学 | 标题准确，结论有事实和条件支撑；不编造性能、收益或效果保证 |
| 医疗、投资话题需要显著提示，避免随意建议 | 按话题注明“不涉及医疗建议”或“不涉及投资建议”，不虚构专业身份，不提供个体用药、治疗或投资指令；声明不能使违规内容变得合规 |
| 尊重隐私、肖像、名誉，保护未成年人及弱势群体 | 不输出侵犯他人权益的内容，不以群体身份、外貌等攻击他人，不冒充他人或编造炫富经历 |
| 交易留在平台内，不在个人页、评论、私信等场景导向站外 | 不生成加联系方式、进群、站外交易等引流话术；必要技术引用与交易引流分别判断 |
| 合作内容基于真实体验，营销不得拉踩、贩卖焦虑或制造群体对立 | 不将推广伪装成亲测，不虚构体验，不攻击竞品或煽动对立 |
| 鼓励友好交流和正常点赞、关注 | 不把“点赞”“评论”“私信”等词本身视为违规；正常提问、感谢和自愿互动可以保留 |

公约还涉及专业号、蒲公英合作等发布与经营行为；生成文案不能替发布者完成认证、报备或平台操作。

## 内部保守约束

以下是本工具主动采取的写作策略，**不宣称已逐条核实为平台最新禁令或限流条件**：

- 不主动添加“私信领资料”“评论扣 1”等资料领取话术，不把点赞、收藏、关注或转发作为领取内容的条件，不虚构抽奖福利或互粉互赞。
- 标签与正文相关，不蹭无关热点、不重复堆词，不添加推广链接；必要官网、仓库或文档引用按来源及输出契约保留，不承诺链接一定被平台允许。
- 不通过谐音、拼音、拆字、符号或藏字规避审核。知识讲解可以客观分析违规案例，不能变成操作建议。
- 不隐瞒已知商业关系或 AI 生成事实，不声称已经完成商业报备或 AI 标识。具体声明和类目要求由发布者核实。
- 不输出“保证过审”“绝不限流”等保证，不把敏感词、发布时段或推荐算法传闻当作确定规则。

例如，无依据的“亲测效率提升 10 倍，私信领取”应改成能够由资料支撑的功能、步骤与限制说明；缺少对照测试时，不保留或另编提升比例。

### 自然介绍产品

涉及产品、项目或网站介绍时，提示词要求按“具体问题 → 解决方法 → 产品如何参与 → 适用条件与限制”组织内容，先给读者能直接使用的方法，再说明有事实依据的功能与作用。这是内部写作策略，服从现有必选章节及字数要求，不强制新增章节，也不将无关教程改成推广稿。

用具体功能说明价值，避免“神器、必备、闭眼入、效率翻倍”等空泛或无依据的推销表达、品牌名堆砌和生硬植入；没有真实体验材料时使用客观功能介绍。关键答案或步骤不设为私信、加群、关注或购买后的条件，不主动添加催购或站外引流结尾。

自然介绍不隐藏已知推广意图和利益关系：资料明确作者是开发者、经营者或合作方时按真实身份表达，不冒充独立用户；已知赞助或合作如实声明。不修改事实、引用与平台规则的约束，也不虚构亲测或对照数据。

## 当前生效范围与限制

- Git、主题、网站生成共用 system 提示词：中文与英文的标题、摘要、正文、标签和关键词默认参考上述小红书风险约束；内容安全优先于 SEO、语气和必选关键词。现有必选词等确定性校验仍执行，冲突可能导致生成失败，需要修改创作要求。
- 主稿继续使用请求的长度、章节和双语结构，不统一压成小红书短笔记。网站主稿仍要求保留来源官网链接。
- SEO 影响属于间接影响：生成文章的真实性和平台约束优先于搜索表达，现有 SEO 结构与校验继续执行；本次未改页面、路由或元数据，私有后台继续禁止索引。
- 平台超限压缩共用通用内容安全提示；仅 `XIAOHONGSHU` 追加小红书专项提示。其他平台专项规则尚未接入。
- 小红书渠道稿继续使用目录默认的标题 20、正文 1000 个 Unicode 码点限制，标签、链接、空白和换行计入正文；这是系统参考值，最终以目标编辑器为准。
- 平台优化仍只改写超限字段，未超限字段原样保留，整篇未超限时不调用 AI。因此该入口不是全文审核或风险清洗，标签元数据也不会被另行审核。
- 历史文稿、手写/粘贴内容及独立英文翻译不会自动重写。翻译保持原意，不承担风险修订职责。
- 没有新增关键词硬拦截、风险评分、发布审批、数据库字段、依赖或配置。正文仍需人工核对；封面、配图、视频、商品、账号行为及平台反馈不在本次验证范围内。

## 验证与维护

`OpenAiCompatibleContentGeneratorTest` 使用本机模拟 AI HTTP 服务，覆盖三类来源的规则注入、自然介绍产品的方法及真实性边界、恶意来源保持在 user 数据中、小红书与其他渠道的提示选择，以及 JSON、双语、长度与独立翻译/连通测试合同。`ChannelCopyOptimizationServiceTest`、`PlatformContentAdapterTest` 验证原有字段保留、字数和适配行为。

执行入口与环境见[开发文档](开发文档.md)。本轮 36 项相关测试通过；这是请求构造与既有校验的回归证据，未调用真实模型，不证明模型一定遵守规则，也没有提交到第三方平台验证审核或推荐结果。

修改规则需同步本页、业务与技术说明。撤回本次功能只需恢复生成器提示词并重新构建；没有数据迁移或旧稿清洗，不需删除数据。正式发布和制品回滚仍遵循[运维文档](OPERATIONS.md)。
