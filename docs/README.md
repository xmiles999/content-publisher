# 项目文档索引

本项目是个人内容生产与发布工具。日常路径为“写稿 → 保存版本 → 确认发布基线 → 发布 → 监测结果”，不引入团队审批或协作后台。

已有英文文件名继续保留，避免破坏引用；新增说明使用中文文件名。以下有效文档由修改对应功能的维护者在同一任务中更新，项目所有者负责最终确认。

| 文档 | 用途与读者 | 维护边界 |
|---|---|---|
| [开发文档](开发文档.md) | 开发者：启动、测试、停止、调试 | 环境、入口、验证命令变化 |
| [详细技术设计](TECHNICAL_DEVELOPMENT.md) | 开发者：架构、模块、数据流、失败模型、测试映射 | 设计与实现变化；是当前设计文档，不是规划草案 |
| [业务说明](FUNCTIONAL_SPEC.md) | 使用者与开发者：规则、状态、权限、限制 | 用户行为、字段和状态变化 |
| [内容生成与发布流程](PUBLISHING_WORKFLOW.md) | 使用者：各内容来源、确认、API/人工发布 | 核心流程和恢复方式变化 |
| [REST API 参考](API_REFERENCE.md) | API 使用者：路径、权限、请求、错误 | 接口合同变化 |
| [OpenAPI 快照](openapi.json) | 工具与集成开发者：机器可读接口合同 | 由 `scripts/openapi` 验证或生成 |
| [配置与部署运维](OPERATIONS.md) | 运维者：配置、部署、健康、备份和回滚 | 启动、部署及运行约束变化 |
| [个人使用精简说明](个人使用精简说明.md) | 项目所有者：本轮取舍、保留能力、验证与限制 | 精简边界与剩余风险变化 |
| [历史工程规范](ENTERPRISE_AI_OPEN_SOURCE_DEVELOPMENT_STANDARD.md) | 维护者：历史工程约束参考 | 不作为团队化产品设计依据；现行开发规则以适用 AGENTS 和统一规范为准 |

阅读顺序：首次开发先看开发文档，再查技术设计；使用流程先看业务说明及发布流程；涉及配置、数据或上线必须查阅运维文档。各文档互相引用，不复制同一套配置表或接口清单。
