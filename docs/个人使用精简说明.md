# 个人使用精简说明

当前新建/人工准备稿持久化、主稿草稿修订号、发布版本门禁和配图下载见[草稿与发布完整性](草稿与发布完整性.md)。下方各日期的验收与限制保留为历史记录，不替代本次实现说明。

## 目标与边界

2026-09-22 的精简以个人写稿和发布为核心，保留监控勘测和流程化控制。2026-09-26 后续优化见[优化实施记录](优化实施记录.md)。沿用 Spring MVC + Thymeleaf 模块化单体，不迁移前端框架，不新增外部依赖、不删除表、不部署。

## 2026-10-26：日常发布入口收敛

- 首页直接进入文稿列表，删除重复工作台模板和概览查询依赖。
- 侧栏常驻文稿、写新稿、发布、渠道；来源入口移到写新稿的“其他写作方式”，其他工具收进“更多工具”，进入对应工具时自动展开。
- 新建默认只需标题、正文；省去重复的直接编写标题、功能提示条和流程解释。
- 文稿搜索与状态常显，来源、语言与页数按需展开；已有筛选时自动展开，搜索、分页及 URL 参数仍有效。
- READY、兼容 APPROVED 和 PUBLISHED 文稿可以在文稿列表直接“去发布”。
- 小屏文稿表格改为文章行，保留标题、摘要、状态、时间和操作，来源与版本不挤占小屏；只读或已确认文章的入口显示“查看”，可编辑草稿显示“编辑”。
- 发布中心默认待发布；渠道覆盖、发布记录与执行批次保留在页内。运行摘要只在执行批次展示。
- 未配置 API 账号时省略文章发布页的空 API 侧栏；人工平台为空时提供渠道设置入口。
- 不删除历史数据、旧 REST 合同、生成来源或监控能力；低频工具退出常驻主流程。无迁移、无新依赖、启动入口未改动。

本轮测试与浏览器记录见下方“本轮验收”；历史验证记录不能替代本轮结果。

## 已实现的精简（历史）

| 编辑页主标题旁的源指纹 | 仍在来源详情保留，不占日常编辑区 |
| 内容库重复说明与“去发布”主按钮 | 内容库主要动作是写稿；发布仍从导航和文章工作区进入 |
| 无人消费的角色显示映射 | 移除展示层死代码，认证和权限校验未删除 |
| 无对应服务的客服挂件自动注入 | 每页请求 `/support-bot/static/widget.js` 返回 404；与个人写稿无关，移除注入与外部助手入口，不影响监控 |
| 全量常驻的设置入口 | AI、自动化、回收站收进“设置与维护”，当前设置页自动展开 |
| 总脚本中的草稿保存实现 | 提取独立小模块，便于回归；不是引入新框架 |
| 编辑页信息区长期占据正文空间 | 摘要、标签和关键词收进“文章信息”折叠区，正文和预览保持主区域 |
| 英文一键生成后的保存状态不明确 | 程序填充英文稿时复用 `input` 事件，自动保存与预览和手工输入保持一致 |
| 人工发布页离开时可能丢失平台内容 | 加入未保存离开提醒，并明确区分“步骤进度自动保存”和“正文在提交时保存” |

## 柔和配色与侧栏（历史）

按本轮补充要求，整体换为雾白/灰绿表面、低饱和绿色主动作；深色为中性灰黑，不再使用大面积蓝绿色底。
色值仍统一归属 `app.css` 明暗主题变量，错误与警告保持独立语义色，不靠降低文字可读性获得柔和效果。

侧栏桌面宽度收敛为 244px；减少分组标题、粗选中条和树枝装饰，选中态使用浅色背景与字重。
仅保留“工作区”“流程与监测”常驻分区，“设置与维护”按需展开。
“文稿”页面不再误高亮“写新稿”来源组，主入口直接编写，不再重复列出相同的子入口。
紧凑图标模式、移动抽屉、键盘焦点和监控/任务导航保留。项目 SVG 标志只调整颜色，不引入外部素材。

## 明确保留

- Git、主题、网站与直接编写四类来源；版本记录、恢复、草稿、本人确认和已发布修订。
- 发布预检、定时、队列、批次、人工步骤、取消、失败诊断和受控重放。
- 渠道连接验证、巡检、失败/恢复通知；监控页面、健康检查、Prometheus 指标。
- 回收站、数据隔离、CSRF、认证、密钥保护、审计、安全 URL 校验和迁移。
- 旧审核 API、历史状态和租户字段仅为兼容保留。删除它们需要单独评估旧数据与客户端，不把移除 UI 误称为移除底层能力。

## 已修正的问题

1. `DISABLED` 首页空认证导致 500，且 Portal 未显示编辑/管理能力：展示层现在按明确的安全模式处理，不改变 LOCAL/JWT 的权限规则。
2. 自动保存正文上限与正式文章不一致：复用 `ArticleLimits`，中英文各 100000；标签、关键词不再静默截断，沿用正式内容限制。
3. 单标签页自动保存并发、旧响应错误确认和旧内容备份：改为串行请求，只确认请求自身的内容修订；失败保留最新编辑内容。
4. 登录重定向/HTML 误当保存成功：要求成功 JSON 与有效时间；错误明确提示，存储失败不宣称已备份。
5. 自动保存与正式提交竞争：提交等待已发送草稿完成，应急备份仅在下一页面确认正式保存成功后清除。
6. 表单校验/业务失败后丢输入：通过 Flash 表单保留本次提交内容。
7. 多模块 `spring-boot:run` 启动链：改为构建 JAR 后启动，补充端口、锁、就绪检查、错误退出和子进程清理。
8. 2026-09-26：覆盖矩阵和待发布使用数据库筛选、分页与计数，不再截取最近 50 篇再筛选；待发布只显示 `READY` 和兼容 `APPROVED`，已发布文稿从覆盖矩阵继续发布。

### 未覆盖与限制（历史记录，当前以本轮验收为准）

- 本轮未做全平台真实发布或外部 AI 调用；监控与流程入口保留不等于外部服务已经健康。
- 同标签页串行保存不等于跨标签页协同锁。多个标签页同时编辑同一个账号的同一草稿，仍应避免；正式版本冲突校验保留。
- 应急草稿仅存当前标签页且按账号隔离，不保证关闭标签页后恢复。历史版本使用的 `localStorage` 应急数据不自动导入，避免错误账号恢复；它们不被本轮批量删除。
- 已确认后禁止新的草稿写入，但本轮没有更改数据库事务隔离或新增跨请求草稿版本号。
- 开发脚本默认暂停 Worker，不擅自开启积压的发布任务；需要明确启用。
- 当前环境无法访问 Docker，真实 PostgreSQL/恢复演练未覆盖；启动合同测试使用替身，真实应用浏览器检查使用隔离 H2 内存库，不修改实际业务数据。
- 图像回读工具不可用，浏览器可保存截图并验证 DOM/交互/布局，但未完成截图视觉验收。
- 当前测试主机没有中文字体，生成的截图还存在中文缺字风险；正式设备使用系统中文字体。没有为截图修改系统字体或引入远程字体依赖。
- `config/dependency-check-suppressions.xml` 中已有临时规则到期日为 2026-09-15；本轮没有延长例外、升级依赖或运行完整漏洞扫描，发布前须执行安全扫描并按结果处理。
