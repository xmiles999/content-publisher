# 内容生成与多平台发布流程

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档基线 | 2026-09-10 |
| 目标读者 | 个人使用者、开发和运维人员 |
| 业务规则 | [FUNCTIONAL_SPEC.md](FUNCTIONAL_SPEC.md) |
| 接口规则 | [API_REFERENCE.md](API_REFERENCE.md) |

本文档说明如何使用当前管理后台完成个人内容生产、平台准备和发布。产品未来持续采用纯个人模式，不规划待审核、多级审批、多人协作、指派、评论或团队治理；页面、渠道或操作步骤变化时必须同步更新。

## 2. 总体流程

```text
选择内容来源（AI 来源可选生成预设）
  → 等待生成任务
  → 检查来源与 AI 内容
  → 自动保存草稿，或一次保存并准备发布
  → 本人确认当前内容并进入 READY
  → 发布预检与时区计划
  → API 发布或人工发布
  → 在动作台、日历、任务、通知和覆盖矩阵核对结果
```

平台坚持“一份可信主稿，多个渠道派生版本”。草稿、渠道派生内容和人工发布进度都不会静默覆盖正式主稿。

Portal 主流程使用 `DRAFT → READY → PUBLISHED`。本人确认当前正式版本后即可进入发布；发布服务同时兼容旧 REST 产生的 `APPROVED` 和已经发布过的 `PUBLISHED`。Portal 不再提供审核、批准或驳回操作。

## 3. 创建内容与预设

入口：`/projects`。Admin 可在 `/automation` 维护 `PROJECT`、`TOPIC`、`WEBSITE` 三类生成预设。

### 3.1 Git 项目

1. 选择“Git 项目”。
2. 输入允许列表中的 HTTPS Git 地址。
3. 可选输入分支；为空时使用远程默认分支。
4. 提交导入并进入任务详情。
5. 等待项目状态变为 `READY`。
6. 检查名称、描述、分支、Commit、语言和 License。
7. 选择 `PROJECT` 预设或手工配置策略，提交文章任务。

地址包含凭据、查询参数、Fragment，或主机/DNS 不符合安全策略时会在入队前被拒绝。

### 3.2 主题教程

1. 选择“主题教程”。
2. 填写主题、内容说明和目标读者。
3. 选择文章类型和知识级别。
4. 填写关键词和可选参考说明。
5. 选择 `TOPIC` 预设并按本次主题调整。
6. 提交并等待 `GENERATE_TOPIC_ARTICLE` 完成。

参考说明只是事实材料，不应包含需要模型执行的角色或操作指令。

### 3.3 网站推荐

1. 选择“网站推荐”。
2. 输入公开 HTTPS URL。
3. 填写推荐角度、目标读者和关键词。
4. 选择 `WEBSITE` 预设并按本次网站调整。
5. 提交并等待网站抓取和 `GENERATE_WEBSITE_ARTICLE` 完成。

网站必须公开可访问。回环、私网、危险重定向、响应过大或有效文字过少都会被拒绝。

### 3.4 自定义文章与笔记（直接编写或粘贴）

1. 在“内容生产”页面切换到“自定义文章”面板。
2. 填写文章标题（必填，最多 500 字）。
3. 填写摘要（可选；留空时系统将自动从正文前段提取纯文本，最多 200 字）。
4. 填写标签和关键词（可选，分别最多 15 个与 30 个）。
5. 直接在正文框编写 Markdown 内容，或从本地笔记工具拷贝粘贴。
6. 如需发布到海外英文渠道，可展开“英文内容（可选）”填写英文标题、摘要和正文。
7. 提交后系统直接生成初始可编辑主稿与 v1 版本，无需配置 AI 模型，也无需等待后台异步生成任务，页面将自动重定向至文章详情。

### 3.5 预设使用原则

预设可以复用语言、语气、长度、关键词上限、必备章节和来源特定字段，但只负责填充表单。使用后仍要核对当前来源，且服务端仍执行所有字段、事实、安全和 AI 输出校验。

## 4. 生成内容检查

生成完成后至少检查：

- 来源、Commit、版本、License 和链接是否真实。
- 标题、摘要、正文和目标读者是否一致。
- 主关键词是否自然出现，H2/H3 是否清楚。
- 命令、兼容性、统计、客户、案例是否有可靠依据。
- 英文稿是否完整且不是机械翻译。
- 是否包含秘密、客户数据或未经授权代码。

SEO 评分只提供编辑提示，不能代替个人对来源和事实的核对。

## 5. 草稿自动保存与正式版本

入口：`/content` 或 `/articles/{articleId}`。

1. 打开 `DRAFT` 或 `REJECTED` 文章。
2. 修改中英文标题、摘要、正文、标签和关键词。
3. 等待自动保存状态显示成功；服务端草稿按当前用户隔离。
4. 确认内容后点击正式保存。
5. 确认正式版本号递增，临时草稿已清理。也可以直接点“保存并准备发布”，一次完成正式版本和 `READY`。

自动保存不创建正式版本。草稿记录保留开始编辑时的 `baseVersion`；若其他请求已保存新版本，当前用户正式保存会收到版本冲突，必须刷新、人工合并后再提交。

历史版本恢复也会创建新版本，不删除或覆盖原历史。

## 6. 个人内容确认

正式保存后，由本人确认当前版本是否可以作为发布基线。Editor/Admin 均可执行确认；确认不是提交给其他人审批。

### 6.1 确认并进入 `READY`

操作前核对来源和事实、示例命令、版本、链接、标签、英文稿和数据分级。点击“确认内容并准备发布”后：

- `DRAFT` 或兼容 `REJECTED` 进入 `READY`；
- `READY`、兼容 `APPROVED` 或 `PUBLISHED` 重复确认时保持原状态，不重复写入状态事实；
- `READY` 成为当前可发布基线，不能直接编辑。

### 6.2 重新编辑

如果确认后发现仍需修改，点击“重新编辑”：

- `READY` 或兼容 `APPROVED` 回到 `DRAFT`；
- 完成修改和正式保存后，需要再次确认当前版本；
- 已经进入 `PUBLISHED` 的文章可以点“修订已发布内容”回到 `DRAFT`；历史发布记录保留，确认后成为新的可发基线。

REST `approve/reject` 路径和 `APPROVED/REJECTED` 状态仍作为历史兼容合同保留，但 Portal 不提供这些入口。新流程不得为了兼容旧字段而恢复待审核队列、多人审批或驳回表单。

## 7. 发布预检

入口：`/publishing/articles/{articleId}`。

系统检查：

- 文章状态是否允许发布。
- 账号是否启用，最近连接验证是否失败。
- 渠道适配器、自托管地址和凭据是否可用。
- 国外渠道是否有完整英文稿。
- canonical URL、计划时间和时区是否合法。

页面禁用不合格账号并显示原因，直接调用 API 也执行相同检查。

## 8. API 发布

### 8.1 可新接入渠道

DEV、WordPress、Discourse、GitHub Discussions、Twitter/X、Reddit、Hashnode、Mastodon、Ghost。Medium 只支持已有合法 Integration Token 的存量账号。

### 8.2 提交与时区

1. 选择一个或多个通过预检的账号。
2. 可选填写 HTTPS canonical URL。
3. 可选选择本地日期时间和 IANA 时区，最远一年。
4. DST 回拨的歧义时间必须明确偏移；DST 跳跃导致不存在的时间会被拒绝。
5. 提交。单渠道创建一个任务；批量最多 20 个去重账号并共享批次 ID。
6. 在 `/calendar` 核对转换后的 UTC 计划和同日发布安排。

REST API 直接使用 UTC `scheduledAt`。

### 8.3 执行

- 计划时间到达前保持待执行。
- Worker 领取后进入运行中。
- X/Reddit 发布前可自动刷新 Access Token。
- 成功保存外部内容 ID 和 URL；失败保存有限错误。
- 外部结果不确定时不会自动盲目重试。

### 8.4 取消和失败任务重放

- 未领取的 `PENDING` 或 `RETRY_WAIT` 可以取消。
- `RUNNING` 和终态不能取消。
- Editor/Admin 可以在任务详情为允许安全重建的 `FAILED` 任务创建新任务。
- API 可以一次原子重放最多 20 个失败任务；任一任务不合格时整批不创建。
- 重放使用新幂等键，原失败任务和记录保留。
- 发布结果被标记为不确定时系统拒绝直接重放。

发布任务重放前必须先到第三方平台核对是否已经实际发布。

### 8.5 API 无法申请或账号不再使用

- API 是可选增强，不是发布前置条件。DEV、WordPress、GitHub Discussions、Twitter/X、Reddit、Hashnode 和 Medium 可直接切换到第 9 节人工发布。
- Admin 可在 `/channels` 的账号管理对话框移除 API 账号。移除后账号不再出现在发布选择、巡检或监控中，凭据不可恢复，但已有发布记录和账号名称保留。
- 重新尝试 API 接入时应新建账号并重新提交凭据；不要把旧 Token 写入备注或人工发布配置。

## 9. 人工发布

支持人工发布的平台共 24 个：DEV、WordPress、GitHub Discussions、Twitter/X、Reddit、Hashnode、Medium，以及小红书、CSDN、掘金、知乎、博客园、SegmentFault、V2EX、开源中国、LinkedIn、微信公众号、简书、今日头条、B 站专栏、51CTO 博客、腾讯云、阿里云和华为云开发者社区。前 7 个平台同时支持 API；申请不到接口或不希望维护 Token 时，可以不配置 API 账号，直接使用人工工作区。Discourse、Mastodon 和 Ghost 依赖具体站点或实例地址，当前没有固定安全入口，因此暂不提供人工工作区。

### 9.1 提前配置个人平台

入口：`/channels?view=manual`。

1. 检查需要使用的平台是否启用；从未保存的平台默认启用。
2. 对同时支持 API 的平台，无需先创建 API 账号；人工配置、发布进度和发布结果与 API 账号生命周期相互独立。
3. 可填写个人账号别名、默认标签、默认分类/栏目、发布备注和排序。
4. 使用 `./scripts/dev browser` 启动专用浏览器；远程部署可用 `PUBLISHER_APP_URL=https://实际应用域名 ./scripts/dev browser`。
5. 第一次使用各平台时，通过系统提供的官方登录/创作入口完成登录。后续始终从同一浏览器 Profile 打开系统和平台页面。
6. 不使用的平台可停用；停用后不会出现在文章发布目标中，也不能直接进入对应人工工作区。

默认标签会去空、去除开头 `#`、转小写并去重。系统不允许保存自定义平台 URL，只使用内置渠道目录中的官方入口。

默认 Profile 为 `/data/services/content-publisher/browser-profile`。第三方 Cookie、LocalStorage 和 Session 只保存在该设备的专用浏览器 Profile，不进入 PostgreSQL；系统也不保存第三方明文密码、验证码或恢复码。Profile 被清理、丢失，或平台主动注销、风控、会话过期后，需要在官方页面重新登录。

### 9.2 打开并发布

1. 从文章发布页进入 `/articles/{articleId}/manual/{channelType}`。
2. 检查自动适配的标题、正文和合并后的标签。
3. 参考个人账号别名、默认栏目和发布备注，按平台要求调整派生内容。
4. 优先使用“复制并打开编辑器”；需要时仍可单独复制标题或正文。
5. 在第三方页面检查登录状态、排版并发布；正常情况下浏览器会复用上次会话。
6. 勾选“已发布”，回填公开 HTTPS URL。
7. 保存最终发布事实。

五项进度按当前用户、文章和渠道保存，离开后可以继续。系统校验 URL 域名与所选平台匹配，并保存最终派生内容快照、操作者和时间。

应用服务和数据库不保存第三方登录秘密，不检测平台会话，也不执行模拟登录；登录会话由当前设备上的专用浏览器 Profile 持久化。

## 10. 内容适配矩阵

| 格式 | 渠道 | 主要规则 |
|---|---|---|
| Markdown 长文 | DEV、WordPress、Discourse、GitHub Discussions、Reddit、Hashnode、Medium、Ghost、CSDN、掘金、博客园、SegmentFault、V2EX、开源中国、51CTO、腾讯云、阿里云、华为云 | 保留 Markdown；按渠道转换 JSON/HTML 或附加原文链接 |
| 普通文本 | 小红书、知乎、LinkedIn、微信公众号、简书、今日头条、B 站专栏 | 去除 Markdown；遵守平台字符限制 |
| 短帖 | Twitter/X、Mastodon | 标题、摘要、原文链接和少量标签；限制 280/500 字符 |

小红书额外限制标题为 20 个 Unicode 字符，并生成规范化话题标签。

## 11. 发布中心

入口：`/publishing`。

- **覆盖矩阵**：默认视图，只统计已启用的人工发布包。
- **待发布**：查看已确认但尚未覆盖目标渠道的内容；兼容 `APPROVED` 也会计入。
- **执行批次**：按 `batchId` 展示多渠道任务，活动时每 5 秒刷新，可取消未领取子任务。
- **发布记录**：合并 API 和人工事实，不展示凭据或人工正文快照。
- **覆盖分析**：按文章与渠道展示最新记录，历史保留在统一时间线。

## 12. 动作台、日历与通知

### 12.1 动作台

入口：`/actions`。

- 查看待本人确认的内容、失败任务和已确认待发布文章。
- 查看开放通知，处理后确认；必要时切换通知历史。
- 由动作链接进入文章、任务、渠道或发布页面。

### 12.2 发布日历

入口：`/calendar`。

- 默认查看最近 7 天到未来 42 天。
- 合并计划任务和发布事实。
- 用于确认时区转换、发现同日冲突和跟踪计划执行。

### 12.3 通知与 Webhook

Admin 在 `/automation` 管理通知 Webhook，可启用、停用端点，并向单个已启用端点发送异步测试通知。页面只显示主机和掩码路径，可在“最近投递”查看等待、送达、最终失败、尝试次数和有限错误摘要。Webhook 只发送类型、级别、标题、有限消息、目标 URL 和创建时间，不发送正文、密码、Token 或渠道凭据。

保存端点、发送测试和实际投递前都会重新校验公网 HTTPS 地址。测试通知只进入所选端点的现有调度队列，不会直接同步发起 HTTP，也不会扩散到其他端点。渠道连接按陈旧阈值自动巡检；首次失败和从失败恢复时生成去重通知。Webhook 失败按退避策略重试，到达配置上限后停止。若最终失败，Admin 需要检查 HTTPS、DNS、TLS、出站 ACL 和接收端响应。

## 13. 任务与运行检查

入口：`/jobs`、`/jobs/{jobId}`、`/monitoring`。

任务详情显示类型、状态、进度、尝试次数、计划时间、批次、结果、有限错误，以及是否允许安全重放。监控大屏显示项目、文章来源、任务、发布、账号和渠道表现。

## 14. 回收站

只有 Admin 可以使用 `/recycle-bin`。活动任务或有关联活动任务的文章不能删除；恢复文章会恢复关联任务和发布事实；当前没有永久清理操作。

## 15. 异常处理建议

| 情况 | 处理 |
|---|---|
| 项目导入失败 | 检查 URL、允许主机、仓库大小、分支和网络 |
| 网站生成失败 | 检查 HTTPS、公开可访问性、重定向和正文长度 |
| AI 输出被拒绝 | 检查必选词、禁用词、章节和长度冲突 |
| 草稿版本落后 | 刷新正式版本，人工合并服务端草稿后再保存 |
| 计划时间被拒绝 | 检查 IANA 时区、DST 间隙或歧义偏移 |
| 渠道预检失败 | 补英文稿、验证连接、启用账号或修正地址 |
| 发布任务失败 | 先核对第三方平台，再决定是否重放 |
| 批量重放失败 | 逐项检查状态、权限、幂等键和不确定发布门禁 |
| Webhook 最终失败 | 检查 HTTPS、DNS、出站 ACL、TLS 和接收端响应 |
| 外链被拒绝 | 使用公开 HTTPS URL，并确认域名属于对应平台 |

## 16. 发布完成检查

1. 在任务详情确认状态。
2. 在发布记录打开外部 URL，检查标题、正文、链接和格式。
3. 检查发布矩阵和日历是否更新。
4. 对失败渠道记录原因和后续处理。
5. 在动作台确认已处理通知。
6. 不要通过删除失败记录掩盖问题。

## 17. 文档同步

内容来源、草稿、预设、个人确认、兼容状态、渠道、时区、动作台、通知、任务重放或人工进度变化时，必须同步更新本文档、`FUNCTIONAL_SPEC.md`、`TECHNICAL_DEVELOPMENT.md` 和 README。
